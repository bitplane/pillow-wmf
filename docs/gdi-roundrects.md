# RoundRect: shared cubic corners and straight edges

The [GDI RoundRect contract](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-roundrect)
specifies a filled, outlined rounded rectangle and does not change the current
position. Corner width and height describe an ellipse, not radii.

Native paths captured before implementation in
[run 35147100299](https://github.com/bitplane/pillow-wmf/actions/runs/35147100299)
establish the construction used here:

- Establish corner proportions from the magnitudes of the logical corner and
  box dimensions, clamping each proportion to one. Map the box to device space.
- If either corner dimension is zero, construct an ordinary Rectangle. This
  also uses Rectangle's null-pen bounds and reserved-outline painting behavior.
- Otherwise use the shared adjusted ellipse bounds, including PS_NULL's
  centre/radius adjustment. Multiply each adjusted half-extent by the logical
  corner proportion, then round to a sixteenth
  of a pixel, with half ties upward.
- Place four canonical ellipse quarters at the four corner centres. Start on
  the right edge near the top and proceed counterclockwise, retaining the
  straight connectors even when their length becomes zero. Close the final
  right edge.

For a box width of 112 and corner width of 21, the adjusted fixed-point
half-extent is 888: `888 * 21 / 112 = 166.5`, which becomes 167, not 166.
The corner diameter is therefore not simply copied into the exclusive drawing
box. Native control points expose this distinction even when PNGs happen to
match.

The later [inside-frame probes](gdi-insideframe.md) establish that those ratios
precede device-coordinate rounding: separately rounding mapped corner and box
sizes is incorrect under fractional scaling.

`ellipse._ellipse_quadrants` now supplies the same canonical cubic controls
for both Ellipse and RoundRect. The latter only translates those quarters and
adds straight connectors. It uses the existing fill/stroke machinery, with no
RoundRect rasterizer or pixel corrections.

## Verification

Eight 16-shape atlases cover zero, small, odd, negative, and oversized corner
dimensions with solid/wide/styled/null pens, solid/null/hatched brushes and XOR.
Four mapping references cover reflection, anisotropic scaling and current
position. Every expected PNG is generated by Windows.

The manual native probe asserts all 54 captured coordinate/type sequences and
compares 288 independent WMFs covering further bounds and sizes, one-pixel-wide
and empty boxes, pens/brushes, background modes, XOR and clipping. Unit tests
retain measured control points and the rounding tie. This is measured coverage,
not an exhaustive claim for all inputs and device states.
