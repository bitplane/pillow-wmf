# Coordinate, state and drawing fixtures

Inputs are generated by `scripts/generate-wmf-fixtures.py`, using the same
recorder as the library. They are standard WMFs on a 128-by-128 white surface.
The four original inputs and PNGs are unchanged. The additional 59 cases ask
specific questions; they do not imply corresponding renderer support.

|recorder as the library. Each expected PNG supplies its comparison canvas size.

| Prefix / group | Question |
| --- | --- |
| `coords-inherited*` | Does playback honor the native helper's initial anisotropic mapping? |
| `coords-identity`, `double`, `half`, `two-thirds`, `independent` | Position and filled-boundary mapping at integer and fractional scales |
| `coords-reflect-*` | Signed extents and reversed rectangle corners |
| `coords-half-ties*` | Positive/negative half-pixel decisions, including translated ties; samples occupy separate rows |
| `coords-origins-offsets` | Logical versus device origin changes |
| `coords-mode-*` | All eight modes, plus changes during playback |
| `coords-fixed-ignores-extents-*` | Fixed-mode ignored setters/scalers, including zero extents |
| `coords-isotropic-order-*` | Window-first versus viewport-first initialization |
| `coords-scale-extents` | Integer extent scaling before point conversion |
| `pen-width-*` | Widths 0, 1 and 3 under identity, X-only and Y-only scaling; mapping changes after selection |
| `pen-null-fill` | Fill with no outline |
| `drawing-lines-octants`, `drawing-line-endpoints` | Direction/tie cases, last-point exclusion and zero-length lines |
| `drawing-rectangle-*`, `drawing-ellipse-*` | Odd/even, wide/tall, one-/two-pixel-wide and empty bounds |
| `state-current-position-mapping` | Mapping changes between MoveTo and LineTo |
| `state-save-restore-*` | Nested saves, absolute/relative restores, mapping, position and pen selection |
| `state-clip-*` | Clip realization before/after mapping, and displacement versus point mapping |

Coordinate cases use pixel markers and null-pen filled rectangles, keeping curve
flattening and pen-width realization out of the basic mapping questions. Thin
and empty primitives intentionally include cases whose native output may be
empty. Paired cases are not assumed equivalent until Windows has rendered them.

## Native observations

`scripts/probe-windows-mapping.py` shares the image renderer's `reference_surface`
context manager. The Windows workflow prints one report containing device
capabilities, reference initial state, mapping transitions, return values,
origins, extents, current position, and sample LPtoDP conversions. Each scenario
starts with a fresh DC. Invalid setters are observed, not silently repaired.

The report lives in the workflow log, not per-image JSON files. It is evidence
for the suite-wide device profile and later exact numeric unit tests; the profile
must be based on the actual report, not an assumed DPI. These observations are
not themselves assertions of Windows compatibility.

### Reference device profile

Capabilities: physical size 271 by 203 mm, device resolution 1024 by
768, logical DPI 96 by 96. These are an explicit suite-wide check in the
probe, run before reference generation. A mismatch stops generation for review;
it does not refresh the profile or goldens automatically.

Observed extents immediately after selecting each mode from the reference setup:

| Mode | Window extent | Viewport extent |
| --- | --- | --- |
| Text | `(1, 1)` | `(1, 1)` |
| Low metric | `(2709, 2032)` | `(1024, -768)` |
| High metric | `(27093, 20320)` | `(1024, -768)` |
| Low English | `(1067, 800)` | `(1024, -768)` |
| High English | `(10667, 8000)` | `(1024, -768)` |
| Twips | `(15360, 11520)` | `(1024, -768)` |
| Isotropic | `(2709, 2032)` | `(1024, -768)` |
| Anisotropic (reselected) | `(128, 128)` | `(128, 128)` |

This rules out deriving every mode's extents from the rounded millimetre
capabilities: low metric does not use `(2710, 2030)` on this runner.

Other observations, limited to the exercised inputs:

- At half scale, coordinates `-15, -3, -1, 0, 1, 3, 15, 127` map to
  `-7, -1, 0, 0, 1, 2, 8, 64` on either axis. These ties are not Python `round()`.
- In arbitrary-unit modes, `SetWindowExtEx(0, 10)` failed unchanged, but
  `SetViewportExtEx(10, 0)` succeeded unchanged. Wine's shared zero-rejection
  assumption is not enough.
- Scaling window extents `(-17, 19)` by `(2/3, 3/2)` produced `(-11, 28)`.
  Scaling those extents by `(1/100, 1/100)` failed unchanged rather than replacing
  zero results with one.
- Fixed text/twips modes ignored the probed extent operations, including zero
  factors, and reported success.
- Both isotropic setter orders ended at `(100, 50)` viewport extents in this
  example, but passed through different intermediate states.
- Nested restores reinstated mapping and logical current position. RTL mapped
  X relative to pixel 127 on this surface and retained anisotropic mode when
  `SetMapMode(MM_TEXT)` was called while RTL was active.

These values exercise mapping state, not a universal rounding rule for every
primitive. See [coordinate mapping](gdi-coordinate-mapping.md) for consumer-
specific conversion boundaries.

## Cycle

1. Generate inputs locally; check byte reproducibility and codec/trace round trips.
2. Push the fixture/tool changes to master. Windows renders only missing PNGs,
   prints the mapping report, and commits the PNGs.
3. Pull the bot commit and inspect the report/images. Promote the numerical
   observations needed by the mapping implementation into ordinary tests.
4. Implement against exact pixel comparisons. Unsupported operations and missing
   references fail; no tolerance or skip is added for new cases.

To intentionally replace a reference, delete that PNG and push. Existing PNGs are never refreshed merely because a
script or WMF changed. Raw files found in the wild remain accepted by the test
discovery; the generator only owns the named synthetic cases above.

Related contracts: [layout](gdi-layout.md), [bitmap transfers](gdi-dib-transfers.md)
and [strokes](gdi-strokes.md). Font rendering remains deferred.
